# Phase 2a closed-loop benchmark (modelled)

**Scope: MODELLED energy and MODELLED completion time, SIMULATED frequency.** Nothing in
this folder is measured. No real energy savings and no novelty are claimed. Results
are reported where our policy loses as well as where it wins.

Generated by `python -m benchmark.closed_loop --outdir evidence/phase2a_closed_loop` at
the clean commit in `PROVENANCE.json` (all parameters and seeds are recorded there).
`SHA256SUMS` covers every generated file plus `PROVENANCE.json` (not this README or
itself). The folder is `-text` in `.gitattributes`. Verify with
`cd evidence/phase2a_closed_loop && sha256sum -c SHA256SUMS`;
`tests/test_closed_loop.py` also regenerates the CSVs and `summary.md` byte for byte.

## Files

| File | Content |

| `summary.csv` | Mean, sample SD, min and max over 20 seeds for each scenario, fraction and policy |

## Model and assumptions

- A scenario is a list of (profile, units) taken from `benchmark/sensitivity.py`, plus
  `io_heavy` and `cpu_heavy`. Each unit is one nominal second of that profile at fmax,
  split into CPU work, I/O wait and idle time with the profile shares of
  `monitor/synthetic.py`, jittered by a seeded Gaussian. 20 seeds per scenario
  (scenario seed x 1000 + 0..19).
- At frequency f a unit takes CPU x (s + (1 - s) x fmax / f) + I/O + idle seconds.
  s is the frequency-insensitive fraction of CPU time. s = 0 is the pure 1/f assumption,
  a model choice; s = 0.3, 0.6 and 0.9 are swept for four key scenarios.
- One CPU; the policy acts once per 1 s tick using the previous tick's counters. Each
  tick's counters go through the existing `compute_signals`; our policies use the
  existing rule classifier and `Policy`. Slowing down raises the observed utilization.
- Energy per tick = 21.6 + 32.4 x (f / 5.1 GHz)^3 x util/100 W (the existing model) x
  tick length. EDP = energy x completion time.
- Frequency ladder 3.8, 4.23, 4.67, 5.1 GHz only (no lower P-states).

## Policies

performance, powersave, conservative (existing Python approximations); ours with K=3,
K=3 with one-step ramp-down, K=1 and K=5; fast-up/slow-down (raise after 1 tick, lower
after 3); adaptive K (start 3, range 2-6; +1 when a change reverses the previous change
within 6 ticks; -1 after 10 calm ticks); and a **schedutil-style approximation**
(1.25 x observed util x fmax rounded up to the ladder, optionally with an I/O-wait boost
that starts at fmin and doubles per I/O tick). The last two are not the Linux schedutil
governor: there is no PELT, no frequency invariance, no rate limit and no uclamp.

| io_heavy | powersave | performance | performance | 5 / 7 / 7 |
| cpu_heavy | powersave | performance | performance | 5 / 6 / 6 |

Under the pure 1/f assumption, **our policy does not win energy, time or EDP in any
scenario.** It sits between performance (fastest, best EDP) and powersave (least energy,
slowest). Example, archived scenario: performance 1481.8 J / 34.00 s / EDP 50381;
ours_k3 1425.2 J / 36.18 s / 51555; powersave 1319.8 J / 41.89 s / 55288. Our variants
do lead the fraction of ticks at the class-appropriate frequency (ours_k1 in most
scenarios), which is expected because that metric uses our own class targets.

## Sensitivity to the frequency-insensitive fraction

With s >= 0.3, powersave has the lowest EDP in all four key scenarios, and ours_k3 beats
performance on EDP (for example archived scenario, s = 0.6: ours_k3 47954 versus
performance 50381) but not powersave. **The ranking depends on the model assumption**,
so this benchmark cannot by itself support a claim that the policy saves energy.

## Limits on interpretation

- Modelled, not measured; one simulated CPU; 1 s decisions; synthetic workloads.
- The static term (21.6 W) dominates the power model, so running slower but longer
  costs little extra static energy, which favours low frequencies on energy.
- The ladder omits the low P-states where real savings occur.
- Class targets and thresholds are provisional; "frac at class target" is defined by
  our own targets and is not a quality measure for other policies.
